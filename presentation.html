The Problem

74 Million Voices Left Behind

They know exactly what to say. Their muscles just won't cooperate.

Caused by
  • 🧠 Cerebral Palsy (~17M globally)
  • ⚡ ALS / Lou Gehrig's Disease
  • 🫀 Parkinson's Disease (~10M)
  • 🩺 Stroke survivors (~80M)
  • 🧬 Traumatic Brain Injury
Why current AI fails them
  • Siri / Alexa / Google: 78–85% wrong words
  • Trained only on healthy, clear speech
  • Cannot adapt to irregular articulation
  • Result: completely shut out from voice tech
Why Machine Learning?

Rule-based fails. Deep learning adapts.

Every dysarthric patient sounds different — there's no fixed pattern to hard-code.

❌ Why Rule-Based Won't Work
  • No two dysarthric patients sound alike
  • Can't handle all 4 intelligibility levels
  • Breaks completely on slurred articulation
  • Doesn't improve — static rules, zero learning
  • Would need custom rules per patient manually
✅ Why Whisper + Fine-tuning Works
  • Transformers learn acoustic patterns from data
  • Transfer learning = 680K hrs of speech knowledge
  • Fine-tuning teaches it the "dysarthric dialect"
  • Self-attention captures irregular speech rhythm
  • Improves continuously with more data
"The model that already understands 99 languages and dozens of accents just needs to learn one more — dysarthric speech."

Technical Deep Dive

Inside the ML Pipeline

What actually happens between pressing the mic button and seeing the text.

1
Audio Capture (Browser)MediaRecorder → WebM blob → AudioContext decodes → Float32 at 16kHz mono → WAV encoded in pure JS
2
Log-Mel SpectrogramWhisper preprocessing — 80-channel Mel filterbank over 30s windows. Each window = one inference call
3
Encoder (6× Transformer layers)2× Conv1D downsampling → multi-head self-attention → 512-dim hidden state vectors per timestep
4
Decoder (6× Transformer layers)Masked self-attention on tokens + cross-attention to encoder → beam search (beam=5)
5
JSON Response (FastAPI)Text + timestamps + no_speech_prob → confidence + language + word count

Training Strategy

Fine-tuning on Dysarthric Speech

We don't train from scratch. We teach Whisper a new "dialect."

Hyperparameters
Learning rate1e-5 (prevents forgetting)
Epochs15 (10 frozen + 5 full)
Batch size8
OptimizerAdamW
Warmup500 steps
Early stopPatience = 3 (val WER)
Why freeze encoder first?

Prevents catastrophic forgetting. The encoder already knows how to listen — we teach the decoder first, then fine-tune everything together at a tiny learning rate.

Technical Pipeline

Step-by-Step ML Pipeline

1
Audio Capture (Browser)MediaRecorder API → WebM blob → AudioContext decodes → Float32 samples → 16kHz mono WAV (pure JS encoder)
2
Feature Extraction (Whisper Preprocessing)16kHz WAV → soundfile reads into numpy array → Whisper computes 80-channel Log-Mel Spectrogram over 30s windows
3
Encoder (Transformer)2× Conv1D downsampling → 6 multi-head self-attention layers → outputs 512-dimensional hidden state vectors encoding acoustic information
4
Decoder (Transformer + Cross-Attention)Masked self-attention on previous tokens → cross-attention to encoder states → beam search (beam=5) generates text tokens autoregressively
5
Output Processing (FastAPI)Text string + per-segment timestamps + no_speech_prob → confidence score → JSON response with language, duration, word_count

Fine-tuning Strategy

Transfer Learning on Dysarthric Speech

Two-Phase Fine-tuning

# Phase 1 (10 epochs) — Freeze Encoder for param in model.encoder.parameters(): param.requires_grad = False # → Only decoder adapts to dysarthric output # Phase 2 (5 epochs) — Unfreeze All for param in model.parameters(): param.requires_grad = True # → End-to-end fine-tuning at low LR

Why Low Learning Rate (1e-5)?

  • Prevents catastrophic forgetting
  • Preserves 680K hrs of learned speech knowledge
  • Gently nudges model toward dysarthric patterns
